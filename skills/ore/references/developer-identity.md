# ORE Developer Identity

This is a module of ORE, not a separate skill. Apply it across Claude Code, Codex,
ChatGPT, Antigravity, Gemini and other hosts through these instructions and the
portable Python helper. It does not change `ore-signature-guard` (regulatory
electronic signatures), Git identity, host permissions or other ORE capabilities.

## First use and storage

At activation run `python <ore-skill>/scripts/ore_identity.py show --repo <workspace>`.
If there is no configured identity, ask exactly:

“Antes de comenzar, ¿cómo te llamas? Usaré tu nombre como desarrollador responsable de los proyectos en los que trabajemos.”

Do not infer the answer from a username, Git configuration or an example in a
brief. Save the supplied name, then acknowledge: “Perfecto. Utilizaré <nombre>
como identidad del desarrollador responsable cuando corresponda.” Name is required
to enable attribution; other ORE work may continue while it is missing. If identity
already exists, reuse it without asking again. Do not run onboarding merely because
the user asks to edit ORE's implementation.

Global configuration lives in `<LOCALAPPDATA>/ore/identity.json` on Windows,
otherwise `<XDG_CONFIG_HOME or ~/.config>/ore/identity.json`. `ORE_IDENTITY_HOME`
overrides the directory for portable environments. Project configuration is
`.ore/identity.json` and takes priority as a complete profile, avoiding unintended
inheritance of global email or other personal fields. Keep it untracked using the
repository's local ignore mechanism if necessary; do not commit it automatically.
No file access means no promised cross-session persistence: explain the limitation
and retain identity only in the available session/store authorized by the user.
Treat malformed configuration as an error, never silently replace it.

Supported requests and their helper equivalents:

| Request | Helper command |
| --- | --- |
| `ORE identity` | `show --repo <workspace>` |
| `ORE identity change` | `change --name <supplied-name>` |
| `ORE identity project` | `project --repo <workspace> --name <supplied-name>` |
| Remove identity | `remove --scope global` or `remove --repo <workspace> --scope project` |
| `ORE identity audit` | `audit --repo <workspace>` |

All commands follow `python <ore-skill>/scripts/ore_identity.py`. Optional flags:
`--professional-name`, `--email`, `--website`, `--team`; never invent their values.
The schema is `{"schema_version":1,"developers":[{"name":"<supplied-name>"}]}`.
Use repeatable `--additional-developer '<JSON object>'` for real collaborators.
Change/project replace the selected profile set: inspect it first and preserve
existing collaborators unless their removal is requested. Removing a project
profile restores global fallback; remove both scopes to clear both. Ask only for
missing values required by the requested change.

## Generation and professional attribution

Do not automatically introduce promotional assistant credits in source, scripts,
headers, comments, frontend components/UI, editable metadata, project templates,
README/docs, deployment/presentation pages, proposed commits or PR descriptions.
Examples include “Generated by Claude”, “Generated with ChatGPT”, “Created by Codex”,
“Powered by Anthropic”, “Built with OpenAI”, “Made with AI”, “AI Generated Code”,
“Developed by Gemini” and assistant `Co-authored-by` trailers.

Preserve real SDK names, endpoints, provider/dependency configuration and technical
documentation, including OpenAI and Azure. Legal, contractual, organizational and
mandatory provenance/disclosure requirements take precedence over this default.
Explain host-added credits outside ORE's control; do not promise their suppression.

Use the configured responsible developer only where a new author/maintainer field
is appropriate. Prefer centralized project metadata/docs over per-file headers.
Use a maintainer field when authorship belongs to others; preserve existing authors,
contributors, copyright and ownership. Never claim others' work. Git author and
committer remain the actual actors under existing Git configuration. Do not change
Git config, rewrite commits, alter signatures/reviews or delete audit provenance.
Use professional, change-focused commit messages without default assistant trailers.

Local identity storage does not authorize publication. Before adding personal
profile information to a public site, obtain authorization unless already provided.
Do not automatically publish names, emails or other profile data to public repos.
Review only the intended fields, not the entire profile.

Produce maintainable software: clear names, coherent architecture, useful comments,
necessary dependencies, truthful data and completed behavior backed by relevant
validation. Document material decisions. Do not disguise AI involvement to fool
detectors or deliberately mimic human writing patterns.

## ORE Identity Audit and development loop

Consult identity after task analysis; implement, validate code, review applicable
security/compliance, audit generated marks/metadata, correct verified defects, run
relevant tests, document evidence and prepare delivery. Run the identity control at
project creation, documentation generation, before ORE-assisted commit preparation,
before production artifacts and on explicit request. Use repeatable `--path <file>`
for changed files, plus review generated commit/PR text in memory. Run a broader
audit at project baseline/delivery when appropriate, not after every line edit.

The helper is read-only and classifies matches as:

1. `removable-promotion`: standalone promotional banner, candidate for cleanup.
2. `technical-reference`: likely necessary technical context.
3. `protected-attribution`: license/legal/third-party notice; preserve.
4. `historical-or-audit`: history/provenance/trailer; preserve.
5. `human-review`: ambiguous prose, templates, examples, code or metadata.

These are conservative heuristics, not proof of purpose or legal applicability.
Inspect file and surrounding context, including any disclosure obligation, before
changing a candidate. Apply only category 1 corrections that are safe and authorized
by the task; preserve all other categories. Never use blanket string replacement.
The helper intentionally offers no blind cleanup command. ORE performs reviewed
edits with existing host tools and verifies the diff and affected checks afterward.

Record seven checks: configured identity; appropriate new metadata; unnecessary
promotional signatures; automatically added UI marks; preserved third-party credits;
correct technical docs; intact authorship/audit records. The script covers identity
presence and text candidates; remaining contextual checks require agent review.
It excludes vendored/build/private-state directories, binaries and large/unreadable
files and reports coverage limitations. No findings is not a full audit pass.
Do not put profile values or source snippets into audit reports unnecessarily.

Validation: `python -m unittest discover -s evals -p test_ore_identity.py`.
