# Selection contract v1

Filter observed availability, restrictions, selection scope, evaluated task level,
required tools, exclusions, locks, effort ceiling, retry history, delegation limit
and budget before ranking. L2 reasoning requires medium or higher; L3/L4 reasoning
requires high or higher when a model exposes effort. Models without effort need
an evaluated capability rating. No price or capability is inferred from a name.

Balanced and Economy rank eligible candidates by supplied total cost, then sufficient
capacity; absent cost, preserve the current eligible configuration conservatively.
Quality prioritizes the highest evaluated capability within restrictions. Custom
requires department preferences; preferences never override filters. Balanced is
the default. Profiles are heuristics, not calibrated success predictions.

Expected total cost includes initial execution, delegation, validation, bounded
retries and recovery. Missing prices, token estimates or any overhead makes total
cost unknown. Cost is not comparable unless the same acceptance and gates remain.
No fabricated success probability or guaranteed savings is permitted.

An eligible different configuration yields awaiting-approval, manual or authorized
metadata depending on mode and an exact ledger match. All current execution adapters
remain manual; even authorized metadata is not a claim of an applied change.

Diagnose environment, tools, permissions, credentials, network, missing context and
ambiguity before escalation. Capability/implementation/test failures require explicit
escalation evidence, a bounded retry count and no repeated configuration in history.
Counts/history are supplied observations; there is no autonomous retry loop.
